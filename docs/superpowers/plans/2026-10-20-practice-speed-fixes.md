# 練功測速四個問題（v1.10，2026-10-20）

使用者回報（10/20）：
1. 超過 10 分鐘都要記，不管有沒有角色 ID 都要變成有效的數據。
2. 加倍券：可選倍率（預設 1.5，1.10～3.00），紀錄完成時跳出來給玩家勾，可填其中幾分鐘有加倍（預設全部），回推真實練功速度。
3. 讀不到地圖（「全部都沒抓到，不只天空之城」）。
4. 角色 ID：**不要認**（使用者第二輪改口）。按分享的時候問要不要填、多一個「下次不要再問我」；不記在電腦裡，只用這次填的（一個人會練很多隻）。

## 查到的原因

- **3 讀不到地圖（根因）**：`locateTitle` 用「地圖」按鈕往左 3.2 個按鈕高（約 35px）當地圖名的範圍。
  但小地圖的寬度跟著地圖走：按鈕貼著面板**右緣**，地圖名靠**左**、緊接在地圖圖示後面。
  基準截圖（森林迷宮Ⅲ）的小地圖剛好只有 120px 寬，地圖名剛好落在範圍裡；
  使用者 10/18 的全螢幕截圖（天空之城）小地圖約 220px 寬，地圖名在 x 50～110、範圍是 x 148～217，一個字都沒讀到 → 每張圖都是「讀不到」。
  基準截圖量的位置：面板 x 3～118（左右兩側是深藍框），圖示框 x 6～43，地圖名 x ≥ 47，按鈕 x 82～118、y 39～50（高 11）。
- **3 次要原因**：地圖名樣板（`public/data/speed-names.json`）是 10/13 產的，10/15 遊戲資料 2.0.0 新增的地圖（天空之城、艾納斯島等）沒補，
  有練功資料的圖裡 21 張根本比不到。
- **1**：`PracticeSpeed.save` 沒填角色 ID 就 `noId` 不送；伺服器 `checkRun` 也要求 2～12 字；資料庫 `char_id NOT NULL`。

## 做法

### A. 地圖（read-map.ts）
- `locateTitle`：從按鈕下面那條純面板（按鈕下緣往下 0.25 個按鈕高）往左走到面板左緣（不是淺藍面板色就停），
  地圖名範圍 = 面板左緣 + 3.85 個按鈕高（跳過圖示框）到按鈕右緣。上下位置不變。
- `findMapButton` 可能先抓到場景裡的橘色長條（全螢幕時左上三成有一大片場景）：改成列出所有候選，`locateTitle` 逐個試，標題過得了檢查的才算。
- 重產 `speed-names.json`（`npm run speed:glyphs`），加測試：`maps.json` 每張有中文名的圖，街道名跟地圖名都要在樣板裡（以後新地圖沒重產會紅）。
- 測試：基準截圖把小地圖「加寬」（標頭的按鈕往右移、面板補寬、地圖名留在左邊）→ 簽章跟原本一樣、認得出森林迷宮Ⅲ；
  再貼到 1920×1080 的場景左上角（全螢幕沒有視窗標題列），左邊放一條橘色長條干擾 → 地圖、經驗都讀得到。

### B. 沒 ID 照存（伺服器＋頁面）
- `checkRun`：`charId` 可以是 null／空字串（→ null）；有填才檢查 2～12 字。
- 資料庫：`ALTER TABLE speed_runs ALTER COLUMN char_id DROP NOT NULL`（schema migration，放 ensureSchema）。
- 排行：每個角色留最好一筆；沒 ID 的用網路位址雜湊（每天換）分組，同一個位址同一天只留最好一筆，畫面寫「匿名玩家」。
- 頁面：拿掉 `noId`，一律送；`saveNote` 沒 ID 時寫「存好了（沒填角色 ID，排行顯示匿名玩家）」。

### C. 分享時問角色 ID（頁面）
- 設定（localStorage `ms-speed`）：拿掉 `charId`（舊的存值不讀），加 `askId`（預設 true）；`isPublic` 照留。
- 按「分享遊戲畫面」：`askId` 是 true → 跳出對話框「要填角色 ID 嗎？」：ID 欄（這次開著頁面填過的會帶上）、
  「排行榜顯示我的 ID」、「下次不要再問我」；按鈕「填好了，開始分享」「不填，直接開始」（兩顆都在使用者點擊裡呼叫分享）。
- 控制卡多一行「角色：○○（改）」／「角色：沒填，存成匿名（填角色 ID）」，點了打開同一個對話框（不開始分享），可以把「下次不要再問我」取消。
- ID 只記在這次開著的頁面（重新整理就沒了）。

### D. 加倍券（伺服器＋頁面）
- 存一筆成功回 `{ ok, ranked, id, token }`；token 是隨機 128 位元，資料庫只存雜湊（`edit_hash`）。
- 一段存好就跳出對話框「這段有開加倍券嗎？」（上一段幾分鐘、拿到多少）：「沒開」關掉；「有開」→ 倍率（預設 1.50，1.10～3.00，可打兩位小數）、
  其中幾分鐘有開（預設整段，1～這段分鐘數）→ 存 → `PATCH /api/speed/runs { id, token, coupon: { mult, minutes } | null }`。
- 先存（當沒開）、回答了再改同一筆：不會因為沒回答就漏存。沒回答的照原始速度上排行。
- 真實速度：`10 分鐘經驗 = 拿到的經驗 ÷（沒開的分鐘 + 有開的分鐘 × 倍率）× 10`；全隊打幾隻也用真實速度回推。
  經驗上限（防灌）照原始速度擋（量到的就是原始的）。
- 資料庫加欄位 `coupon_mult real`、`coupon_min integer`、`edit_hash text`（ADD COLUMN IF NOT EXISTS）。
  `exp_per_10min`、`kills_per_10min`、`ranked` 改成回推後的值；原始速度可由 `exp_gained ÷ duration_sec` 算回來。
- PATCH 只認 24 小時內、同一個環境、token 對得上的那筆；只改加倍券跟回推出來的欄位。
- 排行說明改「數字是 10 分鐘拿到的經驗（有開加倍券的已經扣掉）」。

### E. 文件
- 隱私頁：沒填 ID 也會存（匿名）、加倍券倍率跟分鐘數、角色 ID 不記在電腦裡。
- 設計文件（2026-10-13-practice-speed-design.md）補一段 10/20 改動；驗收腳本 speed-shot.mjs 改用新的對話框。
