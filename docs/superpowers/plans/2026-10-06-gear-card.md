# 能力值＋裝備＋衝卷卡 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 首頁加一張卡，告訴玩家「這個等級的能力值該是多少、該拿哪把武器去哪拿、該衝哪些卷」。

**Architecture:** 研究檔 `data/guides/gear.json`（玩家攻略，附出處）＋遊戲資料，由新的 `pipeline/build-gear.mjs` 編成精簡的 `public/data/gear.json`；前端 `src/lib/gear.ts` 純函式算能力值、挑武器與卷軸，`GearCard.tsx` 顯示在首頁。

**Tech Stack:** Next.js 16 static export、React 19、Tailwind 4、TypeScript strict、vitest、node:test。

**Spec:** `docs/superpowers/specs/2026-10-06-gear-card-design.md`

## Global Constraints

- 全部使用者看得到的字用繁體中文；UI 不准 emoji（.ts/.tsx/.mjs 寫完掃 U+2300–23FF、U+25A0–25FF、U+2600–27BF、U+1F000–1FAFF、U+FE0F）。
- 不編造：只推遊戲資料裡**現在拿得到**的東西；玩家攻略每條要有出處；查不到就不寫。
- 只有 V002 地圖／任務拿得到的東西標 `o: "2026-10-15"`，畫面用 `useBeforeV002()` 決定要不要顯示「10/15 開放」。
- 研究檔上畫面的文字要過 `pipeline/lib/guides.mjs` 的 `lintResearch`（不帶網址、地圖編號、玩家 ID）。
- 沿用 `src/lib/item-view.ts` 的 `canJobUse`／`usableBy`、`src/lib/format.ts` 的 `equipStatValue`（攻擊速度的字），不要另寫一套。
- 職業代碼與名稱以 `src/lib/jobs.ts` 為準（29 職：100,110,111,120,121,130,131,200,210,211,220,221,230,231,300,310,311,320,321,400,410,411,420,421,500,510,511,520,521）。
- commit 以 `v0.27:` 開頭，結尾空一行加 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`；不准推 main、不准 `gh auth switch`；暫存檔只寫 scratchpad。

## 資料格式（Task 2 產出、Task 3 消費，兩邊必須一致）

`public/data/gear.json`：

```ts
type GearSource = {
  /** 幾個商店有賣（items.json 的 sh）；沒賣就不給 */
  shop?: number;
  /** 掉落怪：只收出現在已開放地圖的怪，依怪物等級由低到高，最多 8 隻；map 是牠出現的一張已開放地圖（優先不是 V002 的） */
  drops?: Array<{ m: number; n: string; lv: number; map: number; o?: string }>;
  /** 給這個道具的已開放任務（quests.json 有的）；o：V002 任務（同 src/lib/v002.ts 的規則） */
  quests?: Array<{ id: string; n: string; minLv?: number; o?: string }>;
};
type GearWeapon = {
  id: number; n: string;
  /** 武器種類，照 items.json 的 s：單手劍、雙手劍、單手斧、雙手斧、單手棍、雙手棍、槍、矛、短杖、長杖、弓、弩、拳套、短刀、指虎、火槍 */
  s: string;
  lv: number;            // reqLevel（沒寫當 0）
  atk?: number;          // incPAD
  mag?: number;          // incMAD
  spd?: number;          // attackSpeed
  req?: Partial<Record<"STR" | "DEX" | "INT" | "LUK", number>>;  // reqSTR… 有寫才給
  job: number;           // reqJob 位元（沒寫 0）
  tuc?: number;          // 可衝卷次數
  src: GearSource;
  o?: string;            // 所有來源都是 V002 → "2026-10-15"
};
type GearScroll = {
  id: number;            // 同名同成功率合併後，留拿得到的那個 id（多個就留最小的）
  n: string;             // 卷軸名去掉成功率：「拳套攻擊卷軸」
  slot: string;          // 部位：手套、披風、套服、上衣、褲裙、鞋子、耳環、頭盔、盾牌，或武器種類（短劍 → 短刀）
  stat: string;          // 攻擊、魔力、力量、敏捷、智力、幸運，其他照名字（防禦、生命、跳躍…）
  rate: number;          // 成功率 %
  effect: string;        // 說明裡成功率後面那段原文：「物理攻擊力+2，命中率+1」
  src: GearSource;
  o?: string;
};
type StatKey = "STR" | "DEX" | "INT" | "LUK";
type StatRule = {
  jobs: number[]; label: string; main: StatKey;
  secondary: null | { stat: StatKey; type: "level" | "double-level" | "fixed" | "equip" | "ratio";
    offset?: number; cap?: number; value?: number; floor?: number; ratio?: [number, number] };
  t: string; s: string[]; v: "tw" | "community" | "legacy"; mainstream: boolean;
};
type GearNote = { jobs: number[]; topic: "weapon" | "scroll" | "armor" | "stat"; t: string; s: string[]; v: "tw" | "community" | "legacy"; items?: number[] };
type GearData = {
  builtAt: string;
  weapons: GearWeapon[]; scrolls: GearScroll[];
  rules: StatRule[];
  before?: { t: string; s: string[]; v: "tw" | "community" | "legacy" };
  notes: GearNote[];
};
```

研究檔 `data/guides/gear.json`（Task 1 產出）：`{ researchedAt, statRules: StatRule 但文字欄位叫 text／sources／verified, beforeAdvancement: {text, sources, verified}, gearNotes: GearNote 但 text／sources／verified }`。pipeline 照 build-guides 的慣例轉成短欄位（t／s／v）。

### Task 2: pipeline/build-gear.mjs → public/data/gear.json

- [ ] node:test 先寫（RED）：
  - `parseScroll({n:"拳套攻擊卷軸60%", d:"拳套附加攻擊力提升屬性。 成功率：60%，物理攻擊力+2，命中率+1"})` → `{ n:"拳套攻擊卷軸", slot:"拳套", stat:"攻擊", rate:60, effect:"物理攻擊力+2，命中率+1" }`

### Task 3: src/lib/gear.ts（純函式）＋ loadGear

**Files:** Create `src/lib/gear.ts`, `src/lib/__tests__/gear.test.ts`；Modify `src/lib/data.ts`（`loadGear()`，照其他 loader 的寫法）、`src/lib/types.ts`（GearData 型別，或放 gear.ts 匯出）

**Interfaces（Produces）:**

```ts
export function totalStats(level: number): number;                       // 5L+20
export function weaponTypesFor(job: number): string[];                   // 照 spec 的對照表；0 → []
export function isMagicJob(job: number): boolean;                        // 法師系
export function rulesFor(rules: StatRule[], job: number): { main: StatRule | null; others: StatRule[]; inherited: boolean };
export function statTargets(rule: StatRule, level: number, weapon?: GearWeapon): Record<StatKey, number>;
export function weaponPicks(weapons: GearWeapon[], job: number, level: number): { best: GearWeapon | null; alternatives: GearWeapon[]; next: GearWeapon | null };
export function statShortfall(weapon: GearWeapon, targets: Record<StatKey, number>): Array<{ stat: StatKey; short: number }>;
export function scrollPicks(scrolls: GearScroll[], job: number, weaponType: string | null, main: StatKey | null): Array<{ slot: string; stat: string; options: GearScroll[] }>;
export function closestSource(src: GearSource, level: number): { kind: "shop" } | { kind: "drop"; drop: NonNullable<GearSource["drops"]>[number] } | { kind: "quest"; quest: NonNullable<GearSource["quests"]>[number] } | null;
```

- [ ] vitest 先寫（RED），數字照這些：
  - `totalStats(10)=70`、`totalStats(35)=195`
  - level offset 5（main DEX、副 STR）：Lv.10 → STR 15、DEX 47、INT 4、LUK 4；Lv.50 → STR 55、DEX 207
  - double-level cap 60（main STR、副 DEX）：Lv.20 → DEX 40、STR 72；Lv.45 → DEX 60、STR 177
  - fixed 25（main LUK、副 DEX）：Lv.35 → DEX 25、LUK 162
  - secondary null（main INT）：Lv.40 → INT 208、其他 4
  - equip floor 25、武器需求 DEX 35：Lv.35 → DEX 35、LUK 152；沒給武器 → DEX 25
  - ratio [4,1]（main DEX、副 STR）：Lv.50 → STR 55（4＋round(254/5)）、DEX 207
  - 副屬算出來超過「總點數−12」要夾住
  - `rulesFor`：三轉 111 沒有自己的規則 → 用 110 的 mainstream，`inherited: true`；有自己的就 `inherited: false`
  - `weaponPicks`：只收 weaponTypesFor 的種類、canJobUse、lv ≤ 等級；物理比 atk、法師比 mag；同分攻速小的先、再比 lv 高的；alternatives 最多 2 把、跟 best 不同種類；next＝lv > 等級且攻擊高於 best 的第一把（依 lv 排）
  - `statShortfall`：需求 DEX 35、目標 25 → `[{stat:"DEX", short:10}]`
  - `scrollPicks`：物理職業有「武器種類 攻擊」「手套 攻擊」＋主屬性的部位卷；法師是「短杖／長杖 魔力」＋主屬性，沒有手套攻擊；options 依成功率由高到低
  - `closestSource`：有商店先回 shop；否則掉落怪等級最接近 level 的；再來任務
