# 楓幣匯率頁（v0.96）設計

2026-10-13，使用者逐題拍板。範圍：《新楓之谷：經典版》**雪吉拉**的台幣↔楓幣掛單價格，用看股票／外匯的方式呈現走勢；
同時提供「每天一個匯率」給拍賣查價工具換算台幣。菇菇寶貝之後再說（記憶 maplebook-price-tracking）。

## 為什麼要做

9 月底楓幣快速貶值（巴哈：台幣對楓幣從 1:2 萬掉到 1:4.3 萬）。拍賣查價只看楓幣價，會把貶值看成漲價，
所以要每天的匯率來換算。現有的參考站（maple-classic-wiki.pages.dev/price）只有當下數字、沒有走勢，使用者要的是
像我們股票 App 那樣的 K 線。

## 算法

單位：內部一律存「每 100 元台幣換幾萬楓幣」（記作 `ask100`，跟參考站、8591 標題同單位），顯示時才換算：

- 1 億楓幣＝`1,000,000 ÷ ask100` 元（ask100＝300 → 3,333 元）
- 1 元＝`ask100 ÷ 100` 萬楓幣（ask100＝300 → 3.00 萬）

一次抓取（snapshot）：

1. **每筆的匯率**：從標題「A萬楓幣=B元」（A 可帶小數、可寫「億」）算 `A ÷ B × 100`；跟括號裡的 X 差不到 1 才用它，否則用 X。都沒有就丟掉這筆。
2. **排除**：標題有「代練」、匯率低於 10（萬／100 元）的丟掉（跟參考站相同）。
3. **去離群**：中位數 ± 3.5 × MAD 以外的丟掉；剔完剩不到 3 筆就整批還原。
4. **市價** `ask100`：剩下的掛單照匯率由高到低（＝楓幣由便宜到貴）排，取前四分之一（無條件進位、至少 1 筆）的中位數。
5. **有效掛單少於 20 筆**＝這次 8591 不算數（多半是被擋或頁面改版），改用備援。
6. **成交**：跟上一次 snapshot 比，同一個 `id` 的 `sell_count` 增加 Δ（0 < Δ ≤ 1000）就算 Δ 件賣出：
   成交額 += Δ × 單件台幣價；成交楓幣 += Δ × 單件台幣價 × 匯率 ÷ 100（萬）。只算第 2、3 步留下來的掛單。
   第一次看到的掛單只記基準，不算成交。
7. **價位分布**：留下來的掛單照匯率分桶（桶寬 10 萬／100 元），記每桶幾筆，並記市價那四分之一的上下界。

一天（台灣時間 00:00–24:00）：

- 開高低收：把當天每次 snapshot 換成「元／億」後取第一、最高、最低、最後（單位倒過來，所以不能直接拿 ask100 的最高最低）。
- 掛單數：當天最後一次的有效掛單數。成交額、成交楓幣：當天加總；成交均價（元／億）＝成交額 ÷ 成交楓幣（億）。
- 來源：當天全是 8591 → `8591`；全是參考站 → `ref`；混著 → `mixed`。

均線在頁面上算（收盤價的 5 日、20 日簡單平均）。

### ⚠️ 成交量還沒驗證

8591 很多賣家寫「請勿直接下單，談好後開專屬賣場」，真的交易可能不算在公開掛單的 `sell_count`。10/13 16:27 存了全部 116 筆的基準，
實作期間再比對。**如果 48 小時內全部掛單的 `sell_count` 都沒動**，成交量那張圖改成照實寫「8591 公開掛單看不到成交」，不硬湊、不估算，
並回報使用者。

## 存放與更新（不吃 Vercel 部署額度）

收資料的頻率（每 4 小時）跟網站部署完全脫鉤：

- 資料放在同一個 repo 的孤兒分支 **`fx-data`**（只有資料，沒有程式），並用 `vercel.json` 的 `git.deploymentEnabled` 關掉這條分支的部署
  （`fx-data` 分支上放 `{"git":{"deploymentEnabled":false}}`；dev／main 的 `vercel.json` 也寫 `{"git":{"deploymentEnabled":{"fx-data":false,"price-data":false}}}`，兩邊都擋；`price-data` 是拍賣查價 session 的資料分支，10/13 協調好由這版一起寫，那邊不改這個檔）。
  **第一個工作就是實測**：推一次 `fx-data`，用 commit status／deployments API 確認 Vercel 沒有建置。
  擋不住的備案：資料改放另一個沒接 Vercel 的 repo（deploy key 推送），介面路徑跟著改。
- 頁面在瀏覽器裡直接讀 `https://raw.githubusercontent.com/clarkher/maplestory-tool/fx-data/fx/scania/…`（repo 是公開的，
  raw 有 `Access-Control-Allow-Origin: *`，快取約 5 分鐘）。資料更新不用部署，測試機與正式機看到的都是最新的。

### 給拍賣查價 session 的介面

`https://raw.githubusercontent.com/clarkher/maplestory-tool/fx-data/fx/scania/daily.json`

```json
{
  "server": "雪吉拉",
  "unit": "元／1 億楓幣",
  "updatedAt": "2026-10-13T20:17:05+08:00",
  "days": [
    {
      "date": "2026-10-13",
      "open": 3333.3, "high": 3389.8, "low": 3300.0, "close": 3333.3,
      "closeMesoPerNtd": 3.0,
      "listings": 98,
      "volNtd": 12000, "volMeso": 36000, "vwap": 3333.3,
      "samples": 6,
      "source": "8591"
    }
  ]
}
```

- `close`＝當天最後一次的市價（1 億楓幣＝幾元）；`closeMesoPerNtd`＝同一刻 1 元＝幾萬楓幣。換算：楓幣價 × `close` ÷ 1 億＝台幣。
- `listings`／`volNtd`／`volMeso`／`vwap` 在參考站的日子是 `null`。`days` 照日期由舊到新、一天一筆、沒抓到的日子不出現（不補值）。

## 排程（`.github/workflows/fx-collect.yml`）

- `schedule: cron "17 */4 * * *"`（台灣 08:17、12:17、16:17、20:17、00:17、04:17）＋`workflow_dispatch`。
- 照 data-refresh 的拆法，寫入權限只在最後一個 job：
  - **collect**（`contents: read`、checkout 不留 token）：checkout `fx-data` 讀上一次狀態 → 抓 8591（不用 npm 套件，只用 Node 內建 fetch）
    → 失敗改抓參考站 → 算好新的四個檔 → 存 artifact。
  - **publish**（唯一 `contents: write`）：下載 artifact，只收 `fx/scania/` 底下那四個檔、每個都要能 parse、`samples.jsonl` 只能比原本多（不准改舊行），
    commit 推上 `fx-data`。
  - **notify**：兩個來源都失敗、或 8591 連續失敗 3 次（12 小時，`fail8591 ≥ 3`）→ 開 issue（label「匯率收集失敗」），之後 8591 恢復就留言關掉。
- `concurrency: fx-collect`，不取消排隊中的。
- `run:` 裡不寫 `${{ }}`（一律 env 傳），跟 data-refresh 同一條規矩；workflow 原文用測試鎖住。
- **手動觸發從 main 以外的分支，預設不寫入**（`write` 勾了才推 `fx-data`），避免沒審過的分支程式寫壞資料。

### 參考站的歷史（取代原本的「一次性匯入」）

每次收集都順便抓參考站 `price.json`，把它 `history[]` 裡比 `ref-samples.jsonl` 最後一筆新的市價接在後面。
第一次跑就會把它當時留著的 60 筆（10/08 起）全收進來，不用另外寫匯入程式；之後 8591 抓不到的空檔也能用它補。


## 頁面 `/price/fx`

- 標題「楓幣匯率」，副標「雪吉拉・8591 賣家開價」。查資料頁新開「行情」區放一張卡；`/price` 開頭的網址亮「查資料」（`src/lib/nav.ts` 的 match 加 `/price`）。sitemap 加這頁。
- 由上到下：
  1. **大數字**：「1 億楓幣＝3,333 元」與「1 元＝3.00 萬楓幣」同樣大小並列；跟前一天收盤比漲跌（台灣慣例紅漲綠跌，三角形用 inline SVG，不用 ▲▼ 字元）；
     一行「最後更新 N 小時前・8591 賣家開價，不是成交價」，用備援時寫「參考站數字」。
  2. **日 K＋均線 5／20 日**：手指按住拖（滑鼠移上去）出十字線，讀數顯示那天開高低收（兩種單位）、掛單數、成交額、成交均價、來源。
     均線資料不夠時寫「20 日線還要 N 天」。參考站的日子畫空心 K 棒，自己抓的實心。
  3. **成交量**：每天成交額（台幣）柱狀，跟當天 K 棒同色；參考站的日子沒有柱子並標明「這幾天沒有成交資料」。
  4. **掛單數**：每天收盤時的有效掛單數。
  5. **掛單價位分布**：現在每個價位幾筆，橫條排成像委賣檔位，市價那一區標出來。
  6. **怎麼算的**：掛單不是成交、市價怎麼取、成交量怎麼來、資料來源 8591 與備援參考站（附連結）、多久更新一次。
- **資料不夠時**：不到 2 天不畫 K 線，寫「累積中，還要 N 天」；大數字與價位分布照常。讀不到資料（raw 掛了）就說讀不到、請晚點再來，不放示範資料。
  資料超過 12 小時沒更新，在大數字下面照實寫「資料 N 小時沒更新」。
- 圖自己用 SVG 畫（不加圖表套件）：顏色走站上的 CSS 變數（深淺色都要），刻度、均線、K 棒座標都是純函式，可以單元測試。
  日子多到放不下時圖可以左右滑，預設停在最新。
- **視覺先給使用者挑**：資料收集上線、有真資料之後，先用真資料排 3–4 版做好的畫面截圖（手機 390 寬為主，附桌機）給使用者選，選完才定版。
