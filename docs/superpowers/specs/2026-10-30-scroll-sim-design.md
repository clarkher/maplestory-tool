# 衝卷模擬（競品缺口第 3 項）設計

2026-10-30。競品清單 `docs/research/2026-10-29-competitor-gap.md` 第 3 項「衝卷模擬＋要準備幾張」。

## 為什麼做

玩家衝卷前最常猶豫的是「衝到幾張就停、要先買幾件裝備幾張卷」。查到的競品（小次郎工具箱、Artale Tools、墊卷模擬器）只給平均值或「按一下看運氣」，**沒有一家給「準備多少才有九成機率衝成」**，這是我們要做出差別的地方。

## 使用者拍板（10/30）

- 1A：算「一件衝成機率、平均要幾件幾張、準備幾張幾件有九成機率衝成」；詛咒卷失敗會爆裝也算進去。**不做**「衝一下看運氣」按鈕。
- 2A：只從全新裝備算（不填已經衝了幾張）。
- 3A：卷軸、裝備單價玩家自己填，填了才算錢；沒填不出現錢。
- 4A：新頁，**導覽列不加**；從查資料的卷軸卡、裝備卡點進去。
- 5A：白衣卷軸算進去（失敗用白衣把次數補回來）；混沌卷軸不做。
- 版面 **C**：不先選目標張數，表格列出「要成功 1 張～N 張」每一行（N＝這件可以衝幾次），欄位：要成功（含總加成，例如「3 張（攻擊 +6）」）、一件衝成、平均要、九成機率要準備。最後一行（全成功）底色標楓葉橘。

候選圖：`docs/superpowers/specs/assets/2026-10-30-scroll-sim/C-light.png`、`C-dark.png`；樣式來源同資料夾 `candidates.mjs` 的 `C`（inline style 只用站上 CSS 變數）。演算法樣本 `calc.mjs`（數字已驗：60% 衝 5/5 一件 7.78%、九成要 64 張 29 件）。

## 頁面

路徑 `/plan/scroll`，標題「衝卷模擬」，副標「選裝備跟卷軸，算衝到想要的張數要準備多少。」

上卡（輸入）：
- 裝備（圖示＋名字＋「可以衝 N 次」，按「換」挑）。
- 卷軸（圖示＋名字＋「成功率 60%・物理攻擊力 +2・失敗不會爆」或「失敗 50% 機率爆掉」，按「換」挑；只列這件裝備能用的卷）。
- 開關「失敗就用白衣卷軸補回次數」，開了多一個選項選白衣 10% 或 20%。
- 「卷軸單價（楓幣）」「裝備單價（楓幣）」兩格，白衣開了多一格「白衣卷軸單價」。

下卡（結果表），見版面 C。
- 「九成機率要準備」寫「64 張・29 件」。
- 填了單價：表格多一欄「平均花費」，表下多一行說明九成機率那欄的錢（照「張數×卷軸價＋件數×裝備價」）。沒填：表下寫「填了單價就算得出總共要花多少」。
- 白衣開了：表格多一欄「白衣平均」（平均要幾張白衣）。
- 表下說明：「從全新裝備算；剩下的次數不夠衝到就換一件，不浪費卷軸。成功率照遊戲裡卷軸說明。」
- 詛咒卷：說明多一行「失敗有 X% 機率爆掉，爆掉那件就沒了」。

網址帶 `?eq=<裝備 id>&sc=<卷軸 id>`，重新整理跟分享連結都回到同一組。只帶 `sc`：不自動挑裝備，裝備欄留空、寫「先挑一件裝備」（挑裝備的清單只列這張卷能用的）。只帶 `eq`：卷軸挑這件能用、成功率 60% 的那張（沒有就最高成功率那張）。都沒帶：兩個都空，表格位置寫「先挑一件裝備跟一張卷軸」。

## 算法

一件全新裝備可以衝 N 次（`eq.tuc`），要成功 K 張，卷軸成功率 p、失敗爆裝率 b（不是詛咒卷 b＝0）：

- 每衝一張：成功 → 成功數＋1、次數－1；失敗 → b 機率裝備爆掉（這件結束、算失敗），否則次數－1。
- 成功數到 K 就停（這件衝成）；剩下次數 < 還差的張數就停（這件放棄，不再浪費卷）。
- 衝不成就換一件全新的重來，直到衝成第一件。
- 一件衝成 P；平均要 1/P 件；平均卷軸張數＝每件平均用的張數 ÷ P。
- 九成機率要準備幾件：最小的 m 使 1−(1−P)^m ≥ 0.9。九成機率要準備幾張：把每件用掉的張數分布疊起來，算「累積用到 t 張以內就衝成」≥ 0.9 的最小 t。兩個數字各自是九成（不是同時），畫面就寫「64 張・29 件」不另外說明。
- 白衣卷軸（成功率 q）：一般卷失敗而且沒爆的時候，一直用白衣直到補回那一次（白衣失敗不會爆、不扣次數，照遊戲說明）。平均每次補回要 1/q 張白衣。這時一件不爆就一定衝得成，詛咒卷才會有衝不成。「白衣平均」＝平均要幾張白衣（整個過程，含換件）。
- 100% 卷：一件衝成 100%、平均 K 張、九成 K 張 1 件。

算法用精確計算（動態規劃），不用亂數模擬，數字每次一樣。

## 資料

- 卷軸：`public/data/items.json` 裡 `c:"消耗"`、`s:"卷軸"`。成功率、爆裝率、加什麼、能衝哪類裝備在建置時解析好放進小檔（不要在瀏覽器跑 regex）。擴充 `pipeline/lib/gear.mjs` 的解析（目前遇到詛咒就回 null）或另寫一支，產出 `{ id, n, slot, rate, boom, effect, stats }`；解析不到成功率或部位的卷不收。
- 只收「部位或武器種類開頭」的卷（`SLOT_TOKENS` 那套）；說明寫「可使用的裝備：X」的專用卷只對那件裝備出現；寵物、包包、混沌、活動名開頭認不出部位的不收。
- 爆裝率從說明抓（「失敗時有50%機率道具被破壞」「若失敗時以80%機率物品會破壞」「以50%的機率消失」「以10%機率毀損」這幾種寫法）；寫了會爆但抓不到數字的卷不收（不猜）。
- 白衣卷軸 10%（2049004）、20%（2049005）單獨列。
- 裝備：有 `eq.tuc` 而且 >0 的裝備；部位對應用 items.json 的 `s`（跟 `SLOT_TOKENS` 正規化後的 slot 比）。
- 要有驗證：解析出的卷數量、每張的成功率跟名字結尾的 % 一致（名字有 % 的話），抓不到爆裝率的詛咒卷列出來。

## 工程師讀完補問（10/30）

使用者拍板：
- **查不到來源的卷軸也列（B）**：選單全列；沒有掉落、任務、商店來源的卷，卷軸那欄的說明多寫「目前查不到哪裡拿」。裝備同一套（沒來源的裝備也列，挑選清單裡標同一句）。

我自己定的（使用者可推翻）：
1. **天文數字**：一件衝成 < 0.1% 時，「一件衝成」寫「不到 0.1%」，「平均要」「九成機率要準備」寫「幾乎衝不到」，平均花費欄也寫「—」。演算法不能一格一格累加到 t（樣本 maxT 2000 會壞）：每件張數分布最多 N 格，九成張數用「每件分布的生成函數/卷積到 P 夠小前」或直接用 t 上限＝ceil(items90 × N) 的累積算；P < 0.1% 就不算張數。
2. **部位對照補齊**：頭盔→帽子、全身盔甲→套服、腰帶→腰帶、戒子／戒指→戒指（照 items.json 的 `s` 實際用字）、褲、裙→褲裙；「飾品」開頭的不收。實作時跟 items.json 裝備的 `s` 逐一核對，對不到任何裝備的卷不收。
3. **爆裝寫法**：再加「若失敗有50%機率會破壞道具」；「#c失敗時道具毀損。」沒寫數字的算失敗一定爆（100%），畫面寫「失敗一定爆掉」。
4. **白衣開著時的錢**：白衣一律照平均張數算錢；九成那行說明寫「白衣照平均張數算」。
5. **只帶 eq 進來的預設卷**：攻擊 > 魔力 > 其他（照 stat 字串排），同類挑成功率 60%，沒有就最高那張。
6. **職業開頭的楓葉專用卷**（「法師的…」「海盜的…」，說明寫「可使用的裝備：楓葉之杖、楓葉法杖」）：用裝備名字對 items.json 找 id，只對那幾件出現；名字對不到就不收。
7. **單筆道具頁**：v1.21 沒做道具頁，入口只放查資料道具卡。
8. **同名同成功率的重複 id**：網址帶哪個 id 都認，對到同一張。

## 不做

衝一下看運氣、從半路開始算、混沌卷、祝福／保護／安全／完美還原卷（資料裡沒有）、多張不同卷混著衝、裝備現在的屬性。

## 驗收

- 單元測試：60% 衝 5/5 一件 7.78%、九成 64 張 29 件（`calc.mjs` 的數字）；60% 4/5 → 33.7%、22 張 6 件；詛咒 70% 爆 50% 5/5 → 16.8%、33 張 13 件；100% 卷；白衣開著一般卷一定衝得成；解析器吃上面四種爆裝寫法。
- 瀏覽器：手機 390 跟電腦版各截一張（白天／夜晚），表格不能橫向捲出畫面；從查資料卷軸卡點進來網址帶對、表格有數字。
- 文案不出現英文縮寫、不出現「期望值」「機率分布」這類術語。
