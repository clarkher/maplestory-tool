## 五、自動上線（用戶拍板 2A）

新增 `.github/workflows/release-on-open.yml`。

**觸發**：
- 10/15 台灣時間 08:00 起每 15 分鐘一次（cron 用 UTC）
- `workflow_dispatch`：可手動跑、可演練

**每一輪的步驟**：
1. 打官方公告列表 API（`POST https://maplestoryclassic.beanfun.com/api/Bulletin/FindBulletin`），找 10/15 發佈、標題是開機公告的那則。比對規則用過去的開機公告標題訂，演練時驗證。沒找到 → 結束這一輪。
2. 正式機已經是 V002（`/data/meta.json` 的 `release.levelCap` 是 120）→ 結束。
3. 把 `main` 最新的資料 commit 併進 `dev`（有衝突 → 不上線，開 issue）；跑 `npm ci`、`npm test`、`data:build`＋`data:guides`＋`data:verify`、`npm run build`；資料有變就 commit 回 `dev`。
4. 全過 → 合併「`dev` → `main`」的發版 PR。
5. 每 30 秒查一次正式機 `/data/meta.json`：看到 `levelCap: 120` → 在 PR 留言貼正式網址；20 分鐘內沒看到 → 開 issue「上線檢查失敗」。
6. 任何一步失敗 → 不合併，開 issue 寫是哪一步失敗、附 log 連結。

**沒看到開機公告**：23:45 還沒看到 → 開 issue「今天沒看到開機公告」。

**演練**：10/13 用 `workflow_dispatch` 的演練模式，指定一則過去的開機公告編號、不真的合併，證明偵測、檢查、通知三段都會動。
