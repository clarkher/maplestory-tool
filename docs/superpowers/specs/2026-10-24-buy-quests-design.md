## 哪些任務算

建置時（`pipeline/lib/buy-quests.mjs`）從上游原始任務挑，條件全部成立才算：

- 完成條件有要交的道具、沒有要打的怪
- 每一個要交的道具都能交易：上游 `trade.status` 是 `unlimited`，而且沒有 `flags.quest`
  - 上游把「任務道具」（`quest: 1`，像休咪的錢包、白花）也標成 `unlimited`，但遊戲裡任務道具不能交易、拍賣買不到，所以排除
  - 看的是**任務原本要的那個道具編號**，不是合併後的編號：上游把同名道具併成一筆（紅色藥水 2000000 底下還有不能交易的活動版 2001500），
    交易狀態要查 `tradeVariants` 裡同編號那一筆
  - 查不到交易資料的當作不能交易（寧可少列）
- 只收站上有的任務（`quests.json` 已經濾過開放地區、等級上限、轉職階段）

2026-10-24 上游 2.0.0 實算：只交道具不用打怪 198 個 → 道具全能交易 **100 個**（25 個因任務道具剔除），其中 59 個連前置都不用打怪。

## 資料檔

`public/data/buy-quests.json`（約幾 KB）：

```json
{ "quests": ["2206", "2028", ...], "shops": { "2010000": [ShopRow, ...] } }
```

- `quests`：符合的任務編號
- `shops`：這些任務要交的道具裡，NPC 商店有賣的（`items.json` 的 `sp` 去掉商城樂豆點那幾列）；沒有就不寫

頁面另外載 `quests.json`（任務名、經驗、獎勵、NPC、前置），不載 1.8MB 的 `items.json`。

`verify.mjs` 加檢查：數量在合理範圍、每個編號都在 `quests.json`、每個任務都沒有要打的怪。

## 畫面

`/plan/buy`，用 `PlanShell`（上面有角色列，但不強制填）。

- 開頭說明一段：只列要交的東西全都能交易、不用打怪的任務；任務道具不能交易所以不列；拍賣沒有公開成交價，這裡不寫要花多少
- 篩選：角色填完整才出現 `FilterTag`「只看我接得到的」（`questEligible`＋沒在任務卡按「我做完了」），記在 `useRemembered`
- 一行「共 N 個任務 · 經驗高的在前」
- 一個任務一張卡，照經驗高到低（一樣多的話需求等級低的在前）：
  - 標題＝任務名（連到任務圖鑑那張卡）＋等級；金色一行「經驗 N · 楓幣 N」
  - **要交的東西**：道具圖、名稱、數量（連到道具卡，看哪裡買得到）
    - 商店有賣的，下面一行「商店有賣：〇〇 每個 N 楓幣（NPC · 地點）」，取一個最便宜的；舊版資料標「參考舊版資料，可能有出入」
  - **完成後拿到**：道具圖、名稱、數量，隨機給的標「隨機」並說明「從裡面隨機給一樣」
  - 有前置：「要先做：任務名」（連到任務圖鑑）
  - 底部：接任務的 NPC、地點、「路線」按鈕
- 沒有符合的（開了「只看我接得到的」）：寫「Lv.N 現在接得到的任務裡，沒有買齊就能交的」

入口：查資料「排行與規劃」加一列；sitemap 加 `/plan/buy`。導覽列不動（`/plan` 開頭本來就亮「查資料」）。

## 不做

- 不估拍賣價格、總花費（沒有資料，不編）
- 不判斷道具現在拍賣上有沒有人在賣
- 不加導覽列按鈕
