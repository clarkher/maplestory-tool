# 手寫 ID 變怪物 /plan/rename 設計

日期：2026-11-20　狀態：使用者核可（11/20「A」「1」「OK」「B＋X 調分數」）

## 為什麼做

日本推文「勝手に改名されるゲーム」（大森翔吾，11/16，7,100 萬瀏覽）：手寫名字 → 角色收走多的筆畫 → 剩下的拼成一個字 → 分享。
這種「結果很荒謬、想截圖」的小遊戲靠轉傳擴散。楓谷幫手做楓之谷版，目的是**讓人轉傳、把人帶回站上**（結果連到那隻怪的在哪打／怎麼去）。

## 目標

- 手機上用手指寫遊戲 ID，30 秒內玩完一輪
- 結果好笑、可分享（一張圖＋連結）
- 結果頁連到該怪物的單獨頁（在哪打、怎麼去）

## 非目標

- 不用 AI／不打任何線上 API（每玩一次零成本）
- 不改玩家的任何帳號名稱，「改名」只是遊戲裡的說法
- 不收集、不儲存玩家寫的 ID（全部在瀏覽器裡算；GA 只記玩了、配到哪隻怪）
- 不做排行榜、不做打字輸入（使用者選 1：手寫）

## 反目標（做出來但等於失敗）

- 每次都配到同幾隻怪 → 沒有轉傳點
- 硬配：像度很低也說「你是 XX」→ 不好笑、像壞掉
- 用遊戲角色或《神隱少女》湯婆婆當 NPC（記憶「著色畫只做原創角色」）
- UI 出現 emoji／廉價 icon

## 做法比較（Approaches）

| 做法 | 取捨 | 結論 |
|---|---|---|
| **A. 筆畫對怪物輪廓（選這個）** | 怪圖描成輪廓，挑最貼輪廓又蓋最多的筆畫子集；手機端算、零成本；結果可解釋（像度＝覆蓋率） | ✅ 採用 |
| B. 送 AI 視覺模型判斷像哪隻 | 每次都要錢（× 流量）、慢、結果不可控 | ✗ |
| C. 比字不比怪（原作玩法） | 跟原作太像、沒有用到站上的怪物資料 | ✗（使用者選了 A） |

## 玩法流程

1. **登記書畫面**：原創 NPC＋一張「冒險者登記書」，「請在下面簽上你的 ID」，畫布讓手指寫（滑鼠也行）。按鈕「簽好了」、「擦掉重寫」。
2. **收筆畫演出**：NPC 說「多的筆畫我先收著」，沒被選中的筆畫一條條飛向 NPC 淡出（約 1.5 秒）。
3. **變形演出**：留下的筆畫緩緩移到怪物輪廓上，最後淡入怪物圖（約 1.5 秒）。
4. **結果**：
   - 「你從今天起是「{怪名}」」
   - 「筆畫 {原筆畫數}→{留下數}　像度 {N}%」
   - 按鈕：[分享]（產圖＋連結）、[再寫一次]
   - 連結卡：「{怪名}在哪打／怎麼去 →」連 `/db/monsters/{id}` 單獨頁
5. **配不出來（使用者 11/20 拍板）**：最佳像度低於門檻時，所有筆畫往下亂掉、堆成一坨（物理掉落演出，筆畫自己堆，不用圖示），文案照抄：
   > **拉完了，測出來是一坨。建議換個暱稱。**

   按鈕只有 [再寫一次]、[分享]（分享圖就是那一坨）。

## 比對演算法（我的決定）

離線預處理（build 時，`pipeline/` 或 `scripts/` 一支 mjs）：
- 怪物名單：已開放、站上有單獨頁、`monster_frames/{id}.png` 存在的怪
- 每隻怪：取 alpha 輪廓 → 縮到固定格（例 64×64）→ 抽外輪廓邊緣點＋距離場，存成一個 JSON（或二進位）檔，前端 lazy 載入
- 輪廓太相近的怪去重（避免同模型換色的怪搶位置）

前端（Web Worker，不卡畫面）：
- 筆畫正規化到同一個 64×64 格（保持長寬比、置中）
- 每隻怪：貪婪挑筆畫——每次加入「讓輪廓覆蓋率增加最多、又不跑出輪廓太遠」的那一畫，直到加不動；分數＝輪廓覆蓋率 − 輪廓外懲罰
- 允許每隻怪做少量平移／縮放搜尋（幾組固定候選）
- 取最高分；像度 = 分數換算 0–100%
- **門檻**：顯示像度 < 50% → 一坨。原始分數經過一條換算曲線變成顯示 %，曲線用分布測試調，讓大約 10–20% 的手寫變一坨（使用者選 X）
- 分數接近的前幾名隨機挑一隻，增加變化（同樣的字不一定每次同一隻）

## 畫面與素材

- NPC：原創角色，AI 生圖（一張站姿＋可選一張收筆畫的表情），風格要跟站上設計系統 A「攻略工具」搭
- 登記書：AI 生圖的紙張質感背景
- 實作前先出 **3–4 張已生圖、已排版的候選畫面** 讓使用者挑風格（CLAUDE.md 硬規則）
- 不用 emoji；按鈕照設計系統（選中＝橘框淡底、不准膠囊）

## 分享

- 前端 canvas 產一張圖（1080×1350）：寫的字（原筆畫淡色）＋留下的筆畫＋怪圖＋「你從今天起是 XX」＋站名網址
- 手機用 Web Share API 帶圖；不支援就下載圖＋複製連結
- 連結：`/plan/rename`（不帶玩家的字，避免個資）；OG 預覽圖用一張固定宣傳圖

## 入口

- 網址 `/plan/rename`，新頁不進導覽列（慣例）
- 首頁一個入口、查資料怪物單獨頁底一行「用你的 ID 變一隻看看」
- 頁名暫定「名字變怪物」（命名使用者可改）

## 追蹤

GA 事件：`rename_start`（開始寫）、`rename_result`（`monster_id` 或 `poop`、`score`）、`rename_share`。事件表在 README 同步更新。

## 驗收

- 單元測試：正規化、貪婪挑選、門檻判斷、一坨分支
- 用 10 組實際手寫筆畫（中文、英文、數字 ID）跑分布：配到的怪要分散（同一隻 ≤ 3 次），且至少 1 組落到一坨
- 手機實機畫面截圖（含一坨）
- 演算法在中階手機 < 1 秒（Worker 內）

## 檢查後補的決定（我的決定）

- **連筆會自動切開**：一筆裡面轉角超過約 60° 的地方切成兩段，比對以段為單位；結果卡上的「筆畫 N→M」算的是切開後的段數。不切的話，英文連筆或簽名式 ID 只有一兩筆，演算法沒得挑。
- **工作順序**：設計核可後，比對演算法、預處理腳本、Worker、分布測試先做；畫面等使用者挑完風格再做。
- 開放怪物 113 隻（查資料目前的數字），圖檔 `monster_frames` 都有；入口放首頁 `RouteHome.tsx` 現有的工具清單。

## 留給實作者決定

- 輪廓格大小、平移縮放候選數、懲罰權重（以分布測試調）
- 飛走／掉落動畫細節
- 預處理檔格式（JSON 或 Uint8 二進位）

## 使用者 11/20 拍板

- **風格 B**：站上攻略工具風（設計系統 A），候選圖 B_clean
- **像度 X：調過再顯示**：原始覆蓋分數換算成顯示用 %，目標約一到兩成的人變一坨；頁面註明「像度是遊戲分數」，不當真實準確度
- 頁名先用「名字變怪物」（之後要改再說）
