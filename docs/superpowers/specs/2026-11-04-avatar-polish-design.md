# 紙娃娃 12 項優化（v1.41）

2026-11-04。第一版（v1.40，設計見 `2026-11-03-avatar-sim-design.md`）上測試機後自己玩一輪提的 12 點，使用者說「全優化」、四題「照推薦」。

## 為什麼

玩的當下最想要的是「隨機穿搭很好玩，但按太快回不去、喜歡的部位留不住、每次等 2 秒」；其次是路上看到的小毛病（超大武器被切、小卡要橫滑）跟讓更多人用到（入口、分享預覽、一般裝備）。

**量到的基準**：隨機穿搭從按下到圖換好，中位數 2.4 秒、最久 6.1 秒（測試機 20 次）；20 次有 1 次超大武器（1702861）下緣被舞台切 53px。

**不做**：搬遊戲內商城以外的價錢來源、記住上一套跨裝置、登入／衣櫃（第一版就不做）、自己算圖或加背景（Worker 免費方案每次 CPU 10ms 跑不動）。

## 使用者拍板的

1. **「穿了什麼」版面選 B（兩欄小卡）**：每張小卡左邊小圖、中間類別＋名字（最多兩行）、右邊一顆鎖頭。小卡本體點了照舊（裝備脫掉、髮型臉型膚色跳到那一頁）。標題旁小字「點鎖頭鎖住，點小卡脫掉」。鎖住的那張用楓葉色框＋淡底，鎖頭實心。按鈕移到小卡上面：第一排「隨機穿搭」（寬）「上一套」，第二排「重置」「下載」「分享」。候選圖：`scratchpad mock2`（真頁面換區塊），文字以這裡為準。
2. **分享預覽要做**：只有按「分享」產生的連結才有（一般開頁不花錢）。單次 US$0.30÷100 萬次；1000 萬 MAU 每人每月開 1 條＝1000 萬次＝付費方案內含 US$5／月，3 條約 US$11／月；現在用免費額度（每天 10 萬次，跟練功測速、野王共用）。
3. **「買不買得到」照推薦**：只有商城有賣的（587 件，點裝 2,319 件的 25%，資料跟查資料卡片同一份）格子寫「80 樂豆點」，加一顆「只看商城有賣」。沒資料的什麼都不寫，**不寫「買不到」**。髮型、臉型沒資料（0／720），不標、也不顯示那顆鈕。
4. **首頁入口放角色列下面**，跟萬聖節攻略同一區同樣式：「紙娃娃」／「換髮型、穿點裝，看角色穿起來的樣子」＋箭頭。不是資料載好才出現。不進導覽列（第一版拍板不變）。

## 也跟使用者講過、沒被改的（我的決定）

- **上一套**：換衣服、髮型、臉型、膚色、性別、隨機、重置都算一步；動作、表情、翻面不算，還原時也不動現在的動作、表情、翻面。最多記 30 套，重新整理還在，新開分頁就清空（同一個分頁逛別頁再回來還在）。「上一套」沒東西可回時變淡按不了。沒有「下一套」。
- **鎖定**：鎖住的那一格隨機穿搭不換；挑衣服卡手動換同一格可以（鎖還在）；那一格被脫掉（手動或規則）鎖就解開；「重置」全部解開。髮型鎖連顏色一起鎖、臉型連瞳色。鎖定不進網址、不進分享連結；重新整理還在。
  - 鎖只看格子、不看哪一件：按「上一套」、手動換同一格，鎖都留著，那格變空才解開。換性別時鎖住的髮型、臉型被換成預設，鎖還在。
  - 隨機遇到互斥：鎖套服 → 不挑上衣褲裙；鎖上衣或褲裙 → 不挑套服、另一件照挑；鎖盾牌 → 武器只挑單手；鎖雙手武器 → 不配盾牌；鎖單手武器 → 一樣 50% 配盾牌。
  - 鎖了又換性別：那件新性別穿不了就被 `setGender` 脫掉，鎖跟著解開；留得下來的繼續鎖。
- **超大武器不被切**：舞台照「實際畫到的範圍」決定放大倍數跟地面線，放得下照舊 2 倍、地面線照舊 40px（腳的位置不跳）；腳底下超出才把地面線往上挪，還放不下才縮小（縮的規則同 v1.40，對齊整數像素）。小窗同一套（1 倍、地面線 14px）。
- **一般裝備也能「穿上看看」**：畫得出來的都有（2,183 件）。查資料卡片是時裝或裝備才載 `avatar.json`（壓縮後 54KB，打開卡片才載，第一格不受影響）。
- **下載固定 4 倍**：`renderMode=0&resize=4`，不多一顆按鈕；實測 620×620、16KB，像素不糊。
- **開場隨機**：網址完全沒帶參數才隨機一套（性別男），馬上換成帶穿搭的網址；不先畫白 T 再換。「重置」照舊回白 T 恤、網址變乾淨，這之後在同一頁不會自己再隨機。`?g=1`、`?try=`、任何帶參數的網址都不隨機。
- **跨類別搜尋**：搜尋框不分類別（字樣「搜尋髮型、臉型、裝備名稱」）。打字時分頁都不亮，結果一區一區列（目前分頁那類排第一，其他照分頁順序），區頭「帽子（12）」，上面一行「找到 N 件」；色塊藏起來；一次 40 個是全部類別加起來。打字時「只看商城有賣」照樣篩，髮型、臉型、膚色沒價錢就不列。點分頁＝清掉搜尋、回那一頁（v1.40 規則不變）。膚色也搜得到。
- **換裝中**：從換穿搭那一刻算（含 250ms 等待），超過 150ms 才顯示（快的不閃）：舊圖變淡（0.45）、舞台中間大轉圈、「隨機穿搭」字變「換裝中…」（還是按得下去）。角色圖第一次載（沒有舊圖）照舊中間大轉圈。捲下去的小窗不加隨機、上一套。
- **預載下一套**：按過一次隨機穿搭之後，舞台閒下來就在背景多算一套、先要第 0 格，下次按直接用（不等 250ms）。動作、表情、翻面、性別、鎖一變就重算。瀏覽器開省流量（`navigator.connection.saveData`）不預載。向 maplestory.io 多要的次數約一倍，不花我們的錢。

## 分享預覽怎麼做（我的決定）

- 分享連結改 `/api/avatar/share?<穿搭>`（Vercel、Cloudflare 都走同一支 route handler，`cf/worker.ts` 的 ROUTES 加一條）。`robots` 開放這條（X 等爬蟲會看 robots）。
- 穿搭參數比一般網址多寫：`s`、`h`、`f`、`w` 一定寫（route 手上沒有資料檔，不知道預設），再加 `j`＝這套裡要用日服畫的 id（用「.」接）。route 不讀 `avatar.json`、不連資料庫。
- route 只認數字跟已知的 `p`、`e`，壞值丟掉；缺 `s`、`h`、`f` 就 302 到 `/plan/avatar`（有什麼帶什麼）。圖片網址全部自己組，不接受外部傳網址。
- 回一小頁 HTML：`og:title`「看看我的紙娃娃」、`og:description`「楓谷幫手紙娃娃：換髮型、穿點裝，看角色穿起來的樣子」、`og:image`（maplestory.io 第 0 格、動作表情翻面照這套、`resize=4&renderMode=0`）、`twitter:card=summary`、`x-robots-tag: noindex`；人打開馬上轉去 `/plan/avatar?<穿搭，不含 j>`（`location.replace`＋`meta refresh` 備援）。
- 按分享時順手要一次那張圖（maplestory.io 第一次畫要好幾秒，先畫好爬蟲才不會等到逾時）。
- 網址列手動複製的連結沒有預覽（照舊可以開、穿搭一樣）。
- 透明底沒辦法加底色（`bgColor` 實測無效），預覽顯示平台自己的底色。

## 要小心的

- **Cloudflare 免費方案額度**：這支跟 API、測試機道具圖共用每天 10 萬次；超過當天分享連結可能開不了。正式網域現在還在 Vercel（DNS 沒切），上正式機後這支先跑在 Vercel，切過去才算 Cloudflare 的額度。
- 舞台要讀圖的像素才知道範圍，所以 `<img>` 要 `crossOrigin="anonymous"`。maplestory.io 沒寫 `Vary: Origin`：同一張圖如果快取裡是沒帶 Origin 的版本，帶 crossOrigin 會被擋（v1.40 下載踩過）。要有退路：帶 crossOrigin 載失敗就不帶再要一次、這張圖當沒量到（照 v1.40 算法），舞台不能因此壞掉。兩次都失敗才算載不出來，15 秒逾時算整趟。
- 上一套、鎖不能用 `useVisitState`：它在沒有 Navigation API 的瀏覽器（舊 iPhone）照網址記，這頁每換一件網址就變，重新整理會掉。改存 sessionStorage 固定 key、存字串，壞掉當作沒有。
- 電腦版左邊角色卡是黏著的，小卡變兩欄之後可能比螢幕高：角色卡要在 `lg` 限高、裡面自己捲，不然下面的小卡要捲完右邊才看得到。
- `avatar-shot.mjs` 第 1、2 項假設打開是白 T：要改成帶參數開，另外新增開場那項。
- 上游資料改版漏抽 `sp`（商城價）要擋得到：`verify.mjs` 跟資料測試加下限。
