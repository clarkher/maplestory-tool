# 拍賣查價工具（雪吉拉，自用版）（v0.97，2026-10-13）

使用者問「自動查楓之谷拍賣的機器人可不可行」。結論：自動登入遊戲去查等於外掛（橘子依遊戲管理規則鎖帳號、終止契約，法院有判決），不做。
改做半輔助：遊戲裡每一下都是玩家自己按，工具只負責「複製品名、讀截圖、記價格」。逐題拍板：

1. **價格給誰看**（3）：先做自己用，下一輪再放上網站（裝備卡、算傷害旁邊顯示「雪吉拉最近成交價（日期、幾筆）」）。
2. **查價清單**（A，9 件）：
   - 每天查：手套攻擊卷軸10%、手套攻擊卷軸60%、日之鏢、雷之鏢、寵物速度卷軸100%
   - 每週查（排在週一）：黃色雨傘、雪花鏢、玻璃鞋、轉蛋券
   - 不叫「熱門」（沒有成交量資料），叫「查價清單」。來源：巴哈經典版板的打寶、幣值討論（見文末）。
3. **伺服器**：先只做雪吉拉。
4. **楓幣換台幣**：另開 session（maple-fx）做外匯式走勢頁；這支只讀它的每日匯率。
5. **截圖**（A）：全螢幕一鍵 Win+PrtSc，工具盯截圖資料夾。
6. **讀圖不用 AI**（使用者問「是不是不需要 AI 判讀」）：用 Windows 內建繁中文字辨識。
   10/13 用合成圖測（微軟正黑體 11pt、深底白字）：7 個數字、日期全對；中文錯一兩個字（攻擊→攻鑿、魔法攻擊力→魔法攻力）。
   中文錯字靠「跟剛複製的品名比對」解決，不需要讀對每個字。

這版不做：上網站、菇菇寶貝、任何自動操作遊戲、提醒通知、賣東西畫面的「7日平均交易價」、手機版。

## 遊戲事實（10/13 從使用者本機客戶端字串表抽）

- 楓之谷拍賣的「快速搜尋」只搜道具名稱；字太短會說「搜尋結果太多.請輸入長一點的關鍵字詞」。
- 「市價」分頁：最近交易的道具的屬性、價格、交易日期，可排序。這是成交價，不是掛單價。
- 5 秒內不能連續搜尋。手續費 5%（賣家領錢時扣）。
- 拍賣 8 月曾暫關（巴哈 8/4），工作室在殺價出貨（巴哈 9/28），單筆成交很雜 → 每件取多筆的中間價。

## 玩家怎麼用（第 1 段，已核可）

1. 跑 `npm run price`（或雙擊捷徑）→ 打開本機「查價清單」頁 `http://localhost:9380`。今天要查的列出來：每天 5 件，週一多 4 件。
2. 按「複製下一件」→ 品名進剪貼簿，那一列亮起來。
3. 遊戲裡：拍賣 → 快速搜尋貼上 → 搜尋 → 切「市價」→ Win+PrtSc。
4. 工具看到 `Pictures\Screenshots` 多一張圖 → 對到剛複製的那件 → 幾秒後那列顯示讀到幾筆、中間價。
5. 市價一屏放不下就捲下去再截，都算同一件，直到按下一件。
6. 截圖裡的品名跟複製的對不上 → 那列變黃「對不上，請重截」。

估一件 15～20 秒；每天 5 件約 1.5 分鐘，週一 9 件約 3 分鐘（估的，第一次實測後改成量到的）。
**工具不切視窗、不碰遊戲、不代按任何鍵。**

## 讀圖和存資料（第 2 段，已核可；讀圖改成不用 AI）

### 讀圖

- PowerShell 呼叫 Windows 內建文字辨識（`Windows.Media.Ocr`，語言 zh-Hant-TW），回傳每一行文字＋位置。
- 照位置分欄：市價分頁的欄位位置照使用者 10/13 截的兩張真圖定（手套攻擊卷軸10%、黃色雨傘）。
- 檢查（取代原本「兩個讀法對答案」）：
  1. 品名：跟剛複製那件比，字對上七成以上算同一件。
  2. 有單價、數量、總價三欄時，單價 × 數量要等於總價。
  3. 交易日期不能在未來、不能早於開服 2026-07-29。
  4. 跟這件上次的中間價差 5 倍以上 → 那筆變黃，附截圖那一行給你看一眼。
  5. 一張圖一筆都沒讀到 → 黃「這張沒讀到價格」。
- 黑畫面（整張幾乎同一個暗色）→ 提示「遊戲改視窗或無邊框」。不是市價頁（讀不到市價分頁的欄位字）→ 略過並寫原因。
- **什麼時候改回加 AI**：第一次用兩張真截圖跑，數字有任何一筆跟使用者眼睛看到的不一樣 → 加 GPT 看圖當第二讀法，
  先算一張多少錢給使用者看再接（金鑰在 `C:/Users/user1/auto-short-video/.env`）。

### 存資料

- 每一筆：伺服器（雪吉拉）、品名、價格、單價、數量、交易日期、屬性（裝備才有）、來源截圖檔名、記錄日期。
- 去重：同「品名＋價格＋交易日期＋屬性」只留一筆。同一天同價的兩筆會被算成一筆——寧可少算、不灌水。
- 截圖處理完搬到 `Pictures\Screenshots\已記價\`，留著對帳，不進 repo。
- 按「收工」才寫進 repo 並 push 備份：存在只放資料的分支 `price-data`，不觸發 Vercel 部署（跟 maple-fx 的 `fx-data` 同一招，照它定案的做法）。
- 台幣換算讀 maple-fx 的雪吉拉每日收盤匯率（路徑、欄位照它的 spec）。那邊還沒資料 → 台幣欄寫「匯率資料累積中」，不拿別的數字湊。

## 結果怎麼看（第 3 段，已核可）

查價清單頁下方的「價格表」：

- 每件一列：最近成交中間價（楓幣）、換算台幣、比上次漲跌 %、這次幾筆、最後成交日期。
- 點進去：每天中間價走勢線（楓幣／台幣切換）、所有成交明細、每筆來自哪張截圖。
- 黃色雨傘照屬性（魔法攻擊力）分開算中間價。
- 資料少照實寫：1～2 筆標「只有 N 筆，參考就好」；不到 3 天不畫走勢線，寫「累積中」。

**上網站**（下一輪另外做，這輪不碰網站）：裝備卡、算傷害旁顯示「雪吉拉最近成交價（日期、幾筆）」，資料從 `price-data` 讀；
幾天沒更新就不顯示等細節那輪再給使用者選。另一支 session 在做「練功測速」（分享遊戲畫面、瀏覽器裡認字、Neon Postgres），
到「開放給所有玩家一起回報價格」那輪時，評估改用它那套讀畫面＋資料庫，不要長出兩套。

## 程式怎麼分

全部放 `tools/price/`，不進 Next.js 網站、不加新套件（Node 內建 http、fs.watch、child_process）。

| 檔案 | 做什麼 | 靠什麼 |
|---|---|---|
| `list.mjs` | 9 件清單、今天要查哪幾件（週一加 4 件） | 日期 |
| `ocr.ps1`、`ocr.mjs` | 一張圖 → 每行文字＋位置（JSON） | Windows 文字辨識 |
| `parse.mjs` | 文字行 → 成交紀錄；品名比對、5 條檢查 | ocr 結果、上次中間價 |
| `store.mjs` | 去重、寫資料檔、收工時 commit＋push 到 `price-data` | git |
| `stats.mjs` | 中間價、漲跌 %、台幣換算、屬性分組 | 資料檔、匯率檔 |
| `watch.mjs` | 盯截圖資料夾、配對到目前那件、搬檔 | fs.watch |
| `server.mjs`、`page/` | 本機網頁（清單、複製、價格表、明細） | 上面全部 |

`parse`、`stats`、`list`、`store` 的去重是純函式，可以單獨測；`ocr`、`watch` 包一層，測試時換成假的輸入。

## 驗收
