# 地圖導航：圖上指出要走的門（v2.10）

2026-11-12 使用者拍板：先做「導航圖上指路」，版面選 **B（放大出口附近）**。
別家比較：`docs/research/2026-11-12-map-experience.md`（三張候選圖沒進 repo）。

## 為什麼

現在 `/go` 只列地名，圖要自己點「看小地圖」，圖上也沒標要走哪個門。
別家（NiaMeowDB、Henesys.GG）每一步都有圖、出口框起來寫目的地。

## 做什麼

每一段（最後一段「到了」除外）：

1. 一句話寫在**這張圖**的卡片上：「走最右邊的傳送門，往 海岸草叢Ⅰ」。
   （原本寫在下一張卡：「從上一張圖右邊的傳送門進來」，拿掉。）
   有圖的段落，方向照圈的位置在整張圖的哪一邊（跟角落小圖一致；門名是舊版資料，審查時抓到 `up00` 的門在台服畫在最下面，所以不看門名）；
   貼著地圖邊、查得到位置的門裡沒有更靠邊的才加「最」。沒圖的段落沿用 `portalDirection`，看不出方向就「走傳送門，往 X」。
2. 句子下面直接放圖：整張地圖畫面放大到出口附近，出口畫橘圈、旁邊橘底標籤「往 X」。
   進來的位置（通往上一張圖的門）剛好在畫面裡就畫白點。
3. 角落小圖＝整張地圖，橘框是現在看的這一塊；放在出口另一邊的上角，會蓋到圈或標籤就換別的角，四個角都不行就不放。
4. 不用點開；有這張圖的段落不再放「看小地圖」。

照舊不動：
- NPC 傳送（傑夫）：改寫在這張卡「跟最上面的傑夫說話，他會送你到 X」＋等級門檻那行，不畫圖上的圈。
- 沒有地圖畫面、或查不到門位置的段落：只有那句話＋原本的「看小地圖」。
  （圖鑑內 787 段相連的路，775 段查得到位置。）
- 起點選擇、搭船提示、「到了／看這張圖」。

## 不做

- 地圖頁 `/db/maps/<id>` 的「怎麼去」改版（下一輪）。
- 放大拖曳、標記開關、區域圖入口、10 分鐘經驗（研究報告第 2～4 項）。
- 畫行走路線虛線、一次一張的步進模式（候選 A、C 沒選）。

## 怎麼做（我定的）

- 新資料檔 `public/data/go-doors.json`（`pipeline/lib/go-doors.mjs`，build.mjs 在圖鑑之後寫）：
  `{ <圖 id>: { b: [左, 上, 寬, 高], d: { <目的圖 id>: [[x, y], …] } } }`，只收有範圍 `b` 的圖。
  不直接載 `atlas-maps.json`（311 KB，導航只要門）。
- 載 graph 的頁（首頁、練功…）順手先載這兩個小檔（約 50 KB），進 `/go` 不會多閃一次載入中。
- `/go` 跟 graph 一起載 `go-doors.json`、`map-renders.json`（載不到不算錯，退回純文字），路線第一次畫出來就有圖，不會後來才長高。
- 圖框固定比例 7:4，裁切範圍用遊戲座標算（高度最多 760、不超過地圖），全部用百分比定位：不量寬度、不用 JavaScript 排版。
- 同一個目的地有好幾個門：挑離進來位置最近的，不知道進來位置就挑第一個。
- 純函式放 `src/lib/go-view.ts`（挑門、裁切範圍、最左最右），元件 `src/components/go/DoorView.tsx`。
- 驗收腳本 `scripts/verify/go-door-shot.mjs`。
