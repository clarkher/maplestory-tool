## 玩家看到什麼

- 電腦打開「練功測速」→ 按「分享遊戲畫面」→ 選楓之谷視窗（瀏覽器內建的分享畫面，跟 Discord 開直播同一招）。
  手機打開：寫「要用電腦的 Chrome 或 Edge 開」，不出分享按鈕。
- 第一次用：填角色 ID（2～12 個字），勾不勾「排行顯示我的 ID」（**預設不勾**）。存在這台電腦（localStorage），之後不用再填，可以改。
- 頁面自己認：經驗、等級、職業、地圖、組隊人數（見「從畫面讀什麼」）。
- 左邊大字：**10 分鐘經驗**、**升級還要多久**、這段練了多久、這段拿了多少經驗；模式切換（自動／手動）；狀態（量中／停了／認不到）。
- 右邊：偵測到的地圖 → 這張圖的怪（等級、HP、經驗、掉寶，跟查資料的怪物卡同一份資料）→ 這張圖的排行（單練／組隊兩個分頁，各前 10 名）。
  地圖名旁邊放「帶我去」（我的路線同一套）；每隻怪放「算傷害」連到傷害計算機選好這隻怪（計算機現在不吃網址參數，要小改加 `?mob=<id>`）。這兩個連結就是第 1 題說的「接起來」。
- 小浮窗：按一下用瀏覽器的子母畫面視窗（Document Picture-in-Picture，Chrome／Edge 116 起）蓋在遊戲上，顯示 10 分鐘經驗、升級還要多久、狀態。
  瀏覽器不支援就不出這顆按鈕。
- 導覽列加「練功測速」，只在電腦寬度（≥ 768px）出現；手機導覽列維持四顆。
- 頁面最下面一段：「這是玩家做的工具，不是官方的。只看你分享出來的畫面，不讀、不改遊戲程式。用不用由你決定。」

## 一段怎麼算

- **自動模式**：經驗一動就開始；**60 秒沒動**就停，這段的結束時間算在**最後一次經驗變動**那一刻（不把發呆的 60 秒算進去）。
  換地圖也結束這段（舊圖存一筆，新圖經驗一動再開新的一段）。
- **手動模式**：按開始才算、按停止才停，中間不會自己停、換圖也不停（包含回城買藥的時間，量的是真實效率）。
  地圖記「這段拿最多經驗的那張圖」。
- **10 分鐘經驗**＝這段拿到的經驗 ÷ 這段的時間 × 10 分鐘。只在經驗有變動時才重算（休息時數字不會一直往下掉，巴哈 2 樓的建議）。
- **升級還要多久**＝（這一級升級要的經驗 − 現在經驗）÷ 速度。經驗表用站上現有那份。
- **升級**：經驗變少、等級 +1 → 這次增加量＝上一級剩的 ＋ 新的一級現在的。**死掉**：經驗變少、等級沒變 → 照扣，記一次死亡。
- **存一筆**的條件：這段 ≥ 5 分鐘、經驗有增加。**進排行**的條件：≥ 10 分鐘（10 分鐘經驗才是量到的不是推的）、地圖認得出來、沒超過上限（見「防假資料」）。

## 從畫面讀什麼、怎麼讀

全部在玩家的瀏覽器裡做，**畫面不上傳**。每秒抓一張，只裁需要的小區塊來認（不吃電腦）。
用使用者 10/13 給的視窗模式截圖（1364×799）當基準：

| 讀什麼 | 畫面上在哪 | 怎麼讀 |
|---|---|---|
| 經驗、% | 下方 `EXP 406947[79.73%]` | 數字，遊戲字型固定 → 跟數字樣板比對 |
| 等級 | 左下 `LV. 46`（黃字） | 同上，另一組樣板 |
| 職業 | 左下 `巫師(冰、雷)` | 名單比對：只會是幾十種職業之一，選最像的；對到站上的職業 id |
| 角色 ID | 左下 `芙莉蓮熊芙莉` | **不讀**，什麼字都有、認不準；玩家自己填 |
| 地圖 | 左上小地圖 `迷霧森林`／`森林迷宮III` | 名單比對：街道＋地圖名一起對站上的地圖（站上就是寫 `森林迷宮III`） |
| 組隊人數 | 右側隊伍欄 | 數「名字亮、血條有顏色」的列（含自己）；名字跟血條灰掉的**不算**。看不到隊伍欄＝單練 |

- **找位置**：先用 HP（紅）、MP（藍）、EXP（黃綠）三條的顏色找到下方狀態列，從狀態列高度算出畫面縮放，其他區塊照比例找。
  視窗大小隨便拉都要認得到；認不到就請玩家在頁面上自己框一次。
- **名單比對**（職業、地圖）：先試用跟遊戲最像的系統字型把名單畫出來逐一比；比不準才改用文字辨識套件（只在認地圖、職業時才下載）。實作第一步就用截圖驗這件事。
- **認不出地圖**：提醒「把小地圖打開」；還是不行讓玩家從清單選。職業認不出：用「我的路線」選的職業。
- **背景照常量**：遊戲蓋住瀏覽器時 Chrome 會把頁面當成看不見、計時器變慢。所以讀畫面放在背景執行緒（Worker＋MediaStreamTrackProcessor），
  不支援才退回一般作法。時間都用實際時鐘算，取樣變慢也不會算錯時間。

### 實作時的發現（2026-10-13）

照現在的程式寫，跟上面的表有出入的地方以這段為準：

- **等級不讀畫面上的 LV 小圖**：拿讀到的經驗跟 % 去經驗表反推（46 級升級要 510,420，畫面 406947／79.73% 只對得上 46 級）。
  一定要「剛好一級」對得上才認，兩級以上都對得上（剛升級、經驗很小）或都對不上，這一張丟掉、下一秒再讀。頁面上顯示的 % 也是 經驗 ÷ 升級要的經驗 算的，不用畫面認的那幾位。
- **字形樣板不在瀏覽器裡畫**：事先在 Windows 上用字型畫好、只存縮成格子的特徵（`npm run speed:glyphs`，要微軟正黑體；產出 `src/lib/speed/glyphs.json`、`public/data/speed-names.json`），不存字型本身。
  站上地圖資料多了新地圖名要重跑，不然新圖認不到。
- **小地圖標題**：使用者給的截圖是有損壓縮，小字糊掉，驗不了字型。現在是「標題的長相跟名單（街道、地圖名）比，不夠像就列最像的幾個候選，讓玩家點一次，之後記住」
  （記在這台電腦，差一點點也認）；長相要連續幾張一樣才算換圖，守住不隨時間飄（驗收腳本放 60 秒量這件事）。
  基準截圖上候選通常沒有正確答案，要靠「找不到就搜尋」。**拿到無損截圖再選字型**（客戶端內嵌 Gulim／Dotum／Noto Sans SC，小地圖標題用哪套還沒驗）。
- **小地圖用的是遊戲重畫過的小地圖**，跟站上存的小地圖圖檔（`public/minimaps`）完全不同，不能拿圖比。
- **「認不到就請玩家自己框一次」這版沒做**：狀態列是用紅、藍、黃綠三條的顏色找，不靠固定位置；等實際有人認不到再加。
- **組隊人數不從畫面認了**（上面表裡「組隊人數」那一列、第 6 題作廢）：使用者 10/13 拍板改成玩家自己填，隊伍欄偵測整段拿掉，見下面「10/13 改」。
- **建表不另外跑 `scripts/db/migrate.mjs`**：API 第一次被呼叫時自己 `CREATE … IF NOT EXISTS`（本機沒有資料庫的連線字串，也不用把它交出來）。下面「資料庫」那段寫的 migrate 以這條為準。
- **上限比下面「防假資料」寫的緊**：經驗上限的重生秒數照每隻怪實際的（資料裡 0＝預設 7 秒），最少算 5 秒，不是一律 5 秒；另外加「全隊 10 分鐘打幾隻」上限（每個刷怪點 600 ÷ 重生秒數加起來 × 3，`mapKillCap`），組隊紀錄超過就不進排行（自己等級很低、跟高等隊友吸經驗時，經驗沒超過上限，回推的隻數卻會大到不可能）；經驗是 0 的也不進。
- **驗收**：`scripts/verify/speed-shot.mjs` 用 `window-1364.png` 做成假的分享畫面（頁面在非正式機認 `window.__speedTestStream`），跑完整流程並截圖；
  畫面是靜止的，量不到經驗變動、自動停、存進排行，那幾項靠 `tracker.test.ts` 跟真人玩。

## 資料庫

- **Neon Postgres**（Vercel 直接接，免費方案）。新套件只加 `@neondatabase/serverless`。連線字串 `DATABASE_URL` 由 Vercel 整合自動放進環境變數。
- 一張表 `speed_runs`，每段一筆：

| 欄位 | 說明 |
|---|---|
| id, created_at | |

| map_id, map_name | 認不出地圖時 map_id 空著 |

| char_id, is_public | 角色 ID、這筆是否公開 |
| party_size | 1＝單練 |
| mode | `auto`／`manual` |
| started_at, duration_sec | |

| level_ups, deaths | |
| ranked | 有沒有進排行（≥ 10 分鐘、有地圖、沒超上限） |

  - `POST /api/speed/runs`：存一筆；伺服器自己算 exp_per_10min、ranked、ip_hash、env。
  - `GET /api/speed/board?map=<id>`：`{ solo: 前10, party: 前10 }`，快取 5 分鐘（`s-maxage=300`）。
- 還沒建資料庫（沒有 `DATABASE_URL`）：頁面照樣能量，存的時候寫「排行還沒開，這段沒存到」，排行區塊寫一樣的話。

## 排行

- 每張圖兩張：單練（party_size = 1）、組隊（≥ 2）。只算 `ranked = true`、同一個 env。
- **每個角色只留最好的一筆**（同一個 char_id 取 exp_per_10min 最高的）。
- 顯示：名次、ID（沒公開寫「匿名玩家」）、職業、等級、10 分鐘經驗、練了幾分鐘、日期。
- **掛名要「最好那筆」跟「最新那筆」都勾公開**（10/13 使用者選 B）：沒登入，任何人都能用你的角色 ID 送一筆；這樣別人只能把你藏起來、不能幫你翻開。之後改成不公開，舊紀錄也一起變匿名；以前不公開的成績之後改公開不會跟著掛名。

## 防假資料

- 同一個 ip_hash 一分鐘最多存 6 筆，超過回 429。
- **上限**：這張圖每隻怪的經驗 × 刷怪數 × (600 秒 ÷ 5 秒重生)，再 × 3（組隊加成、活動、經驗卷的寬限）。重生故意用 5 秒，算得偏寬。
  超過照存，但不進排行。
- 等級 1～120、時間 5 分鐘～6 小時、經驗不能是負的，不合理就回 400。
- 誰都可以直接打 API 送假資料，這擋不完，只擋得住離譜的。排行旁邊寫「玩家自己量的，沒有驗證」。

## 成本（口徑：每人每月練 30 段，一段寫一筆）

- 每段一次：後端呼叫 1 次、存 1 筆約 200 bytes。排行有 5 分鐘快取，讀的次數跟人數無關，每張圖最多每 5 分鐘查一次。
- **1000 萬人**：每月 3 億次呼叫 ≈ US$180（Vercel 每 100 萬次 $0.60）；資料每月多 60GB → 要升 Neon 付費方案。
- **免費方案撐得住的量**：Vercel 每月 100 萬次呼叫 ≈ 3.3 萬人；Neon 0.5GB ≈ 250 萬筆。快到再提出來決定。
- 讀畫面全在玩家電腦上，我們這邊 0 成本。

## 隱私、測試截圖

- 隱私頁加一段：這頁會收角色 ID（玩家自己填的）、練功紀錄、網路位址的雜湊；畫面本身不上傳。
- 測試用的遊戲截圖會進 repo（**repo 是公開的**）。截圖裡隊友的名字打馬賽克（亮暗保留，不影響判斷有沒有在線）；你自己的角色名照留，不想留也可以打掉。

## 驗收

- 單元測試：拿截圖原尺寸、0.75 倍、1.5 倍、2 倍跑辨識，經驗、%、等級、職業、地圖、組隊人數（截圖裡是 1：兩個隊友灰掉）全部要對。
- 一段的計算（升級、死亡、60 秒自動停、手動不停、換圖）用假的經驗序列測。
- 無頭 Chrome：用截圖做成假的分享畫面跑完整流程，拍頁面跟小浮窗。
- 資料庫：測試機真的存一筆、排行讀得出來；正式排行看不到測試機的資料。
- 遊戲蓋住瀏覽器 10 分鐘，計時跟取樣還在跑（在使用者電腦上量）。

## 要使用者做的（只有你能做）

1. 在 Vercel 專案頁按一次建立 Neon 資料庫（免費方案）。步驟到時候給；建好之前頁面照樣能量，只是存不了。
2. 再兩張截圖，用來驗收（不擋開工）：**全螢幕**一張；**隊友在線**一張（最好同時有一個同地圖、一個不同地圖），確認「不同地圖的隊友」是不是也灰掉。
   確認前先照「灰的不算」。

## 10/13 改：組隊改玩家自己填（使用者中途拍板）

原話：「組隊辨識太複雜了 讓用戶自己填！有勾選組隊 再請用戶輸入幾人跟個別等級 也能算出這張圖每隻怪 打到的人跟吸經驗的人可以獲得多少經驗 來回推！」第一題 A、第二題 B。

- **不從畫面認組隊**（拿掉 read-party）。玩家勾「組隊」→ 填其他隊員的等級（最多 5 人），選「誰打怪」（自己或某個隊友）。自己的等級照畫面讀到的。存在這台電腦。
- **公式**（第一題 A，出處 [Artale 組隊經驗計算機](https://artale-tools.archie-design.app/tools/party-exp-calculator)，頁面寫 2026-08-08 實機驗證；台服沒驗證，畫面標出來）：
  - 白字：打到的人＝怪經驗×20%＋怪經驗×80%×自己等級÷有效隊員等級加總；吸經驗的人只有後半段
  - 黃字＝白字×組隊加成：有效隊員 2～6 人 +10／20／30／40／50%
  - 有效隊員：跟打怪的人等級差 ≤ 5，或自己等級 ≥ 怪物等級 − 5（原文「符合任一條件」，「目標隊員」解讀成打怪的人）
  - 沒算：祈禱、經驗卷、活動、多人一起打的輸出比例、怪物等級差懲罰（一隻怪假設只有一個人打）
- **每隻怪**（右邊怪物卡）：勾組隊時多一行，列每個隊員打一隻拿多少（打怪的人、每個吸經驗的人）。
- **回推**：你量到的 10 分鐘經驗 ÷ 你這張圖平均每隻拿多少（照刷怪點數加權）＝全隊 10 分鐘打幾隻；再乘每個隊友每隻拿多少＝隊友 10 分鐘各拿多少。
- **排行**（第二題 B）：組隊分頁照「全隊 10 分鐘打幾隻」排（伺服器用同一套公式自己算，不信頁面送的）；單練分頁照舊照 10 分鐘經驗排。
- 資料庫多存：其他隊員等級（陣列）、誰打怪、全隊 10 分鐘打幾隻。組隊人數＝1＋其他隊員數。
