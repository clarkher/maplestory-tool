# 全站改版：A「攻略工具」設計系統（2026-11-09）

## 為什麼改

使用者原話：「整體網站的 Design system 很 AI、很陽春、很醜，我想要有質感的攻略網站。」

現在的設計方向寫在 `src/app/globals.css` 開頭：「楓之谷復古感 × 現代玻璃質感」。
看起來廉價的原因是這幾樣疊在一起：咖啡色斜格紋底（`body` 的兩層 `repeating-linear-gradient`）、
毛玻璃（`glass`／`glass-solid`）、木框雙線（`wood-frame`）、到處都是大圓角（`rounded-xl` 106 處）
和膠囊（`rounded-full` 139 處）。

## 使用者拍板的

- **方向：A「攻略工具」**（11/09，四選一：A 攻略工具／B 雜誌閱讀／C 編輯部／D 楓谷攻略本）。
  參考 Maxroll、Mobalytics：深灰底、1px 細框、小圓角、只有一個橘色當重點色、遊戲圖當主視覺。
- **A 要套全站**，不只攻略文（11/09 問過「除了攻略文章的 UI 也都適用嗎」，看過首頁、查資料、怪物頁、淺色版後說「照 A 寫文件」）。

候選圖（改版的對照基準）：`docs/design-candidates/`
- `候選-A.png`：攻略文（僧侶 31～50），電腦＋手機
- `A-home.png`：首頁第一次來
- `A-db.png`：查資料入口
- `A-mob.png`：怪物頁（青龍）
- `A-mob-light.png`：淺色版

這幾張是用靜態 HTML 畫的示意，不是 React 元件；改版時以「看起來像這幾張」為準，不是逐像素照抄。

## 目標

1. 第一眼像現在主流的遊戲攻略站，而不是範本或 AI 生出來的頁面。
2. 一套規則套全站：攻略文、首頁、查資料、單筆資料頁、各工具頁看起來是同一個網站。
3. 深色、淺色兩套都好看（使用者目前可切換，照系統預設）。
4. 手機優先：台灣玩家多半用手機看。

## 不做的

- 不改內容、文案、功能、網址、資料。這一輪只改長相。
- 不改版面結構裡已經拍板過的東西（例如攻略文手機版全部收合 v1.78、手機導覽列四顆平分 v1.72、
  導覽列項目順序 v1.86）。只換它們的樣式。
- 不加新區塊、新按鈕。候選圖裡怪物頁的「帶我去最近的圖」「算我打牠幾下」是示意，
  **站上已經有的入口才放，沒有的不加**。

## 會讓這次改版算失敗的事

- 改完有任何一頁比現在難用（字變小、按鈕變難按、資訊變難找）。
- 小字對比掉到 WCAG AA 以下（v0.81 拍板全站 AA）。
- 換頁第一格跳動、CLS 變差（見記憶「換頁第一格的坑」）。
- 為了「有質感」加 emoji、圖示庫、假圖。

## 設計規則

### 色彩（token）

**做法：保留現有 token 名稱，只換值。** 全站 120 個 .tsx 檔用 `var(--maple)`、`var(--paper)` 這些名字，
改名要動上百個檔、風險高；換值一次就能讓全站換色。名字跟新意思對不上的，在 `globals.css` 註解寫清楚。

| token（沿用） | 新意思 | 深色 | 淺色 |
|---|---|---|---|
| `--paper` | 頁面底 | `#0c0e12` | `#f5f6f8` |
| `--paper-deep` | 區塊底（表頭、輸入框底、次要面） | `#1a1e26` | `#eceef2` |
| `--paper-edge` | 細框線 | 約 `#464d5a`（要對頁底至少 2，見下） | `#e1e4ea` |
| `--glass`／`--glass-strong` | 卡片底（不再透明） | `#14171d` | `#ffffff` |
| `--glass-shadow` | 拿掉陰影 | `none` | `none` |
| `--ink` | 主字 | `#e8eaef` | `#14171d` |
| `--ink-soft`／`--ink-faint` | 次要字 | `#a3abb8`／`#949cab` | `#4f5765`／`#5d6574` |
| `--maple` | 唯一重點色（橘） | `#ff7a3d` | `#c2410c` |
| `--maple-wash` | 橘色淡底 | `#ff7a3d1f` | `#c2410c14` |
| `--sky` | 「站上計算」標籤 | `#7cc4ff` | `#0b5cad` |
| `--gold` | 「台服回報」標籤 | `#ffb547` | `#8a5300` |
| `--leaf` | 好／成功 | `#5fd38d` | `#17803d` |
| `--wood`／`--wood-deep` | 原本木框色，改成中性灰（框線、捲軸） | `#3a4150`／`#2a303b` | `#c4c9d2`／`#a9afba` |
| `--on-accent` | 橘底上的字 | `#1a0d05` | `#ffffff` |
| `--grid-line` | 不再用（底紋拿掉） | `transparent` | `transparent` |

夜晚框線不能照候選圖的 `#242934`：使用者之前選過「夜晚的框要看得出來，跟頁底對比至少 2」（`global-css.test.ts` 有測），
候選圖那條只有約 1.3。所以框線會比候選圖亮一點。

上表數值是起點；**每一組都要過 `scripts/verify/contrast-audit.mjs`**，不過就調深／調亮到過，不准降標準。
楓幣匯率頁的 `--fx-*` 紅漲綠跌照舊，只把 `--fx-panel`／`--fx-surface` 對到新的底色。

重點色只有橘色一個。藍、金、綠只用在「來源標籤」跟「好／壞」這類有意義的地方，不拿來裝飾。

### 底、面、框

- `body` 拿掉斜格紋跟頂端暈光，純色底。
- `glass`／`glass-solid`／`glass-fill`／`wood-frame` 四個 utility **保留名字、改成實心卡片**：
  卡片底色＋1px `--paper-edge` 框、不模糊、不加陰影。用到它們的 120 多處不用改。
- 導覽列：實心底＋下緣 1px 線，選中的那頁用橘色底線標示（不是橘色膠囊）。

### 圓角

- 卡片、面板：8px
- 按鈕、輸入框、選項：6px
- 標籤（站上計算、台服回報這類）：4px
- 頭像、紙娃娃圓框：照舊圓形
- **膠囊（`rounded-full`）只留給頭像和真正的圓點**。按鈕、選項、標籤一律改回上面的小圓角。
  `rounded-full` 139 處要逐一判斷，不能全域替換。
- `@theme` 裡重設 `--radius-xl`（12px→8px）、`--radius-2xl`（→10px），`rounded-xl` 106 處自動跟著變。

### 字

- 中文照舊 Noto Sans TC（已用 `next/font` 載）。
- 英文和數字加 Inter（用 `next/font/google` 載，不要用 `<link>`），放在字型堆疊前面。
- 數字一律等寬（`font-variant-numeric: tabular-nums`），表格、數值格、等級、HP、經驗都用。
- 標題字重 800、字距略收（`-0.01em`）。內文 16px、行高 1.85（攻略文）／1.6（工具頁）。
- 小標（「先講結論」「本篇目錄」「出沒地圖」這類）：12～13px、字重 800、字距加寬 0.08～0.12em。

### 元件長相（照候選圖）

- **主要按鈕**：橘底、深字（深色）／白字（淺色）、6px、高 40px（手機 ≥44px，`tap-safe`）。
- **次要按鈕**：透明底＋1px 框。
- **選項（職業、等級段這類）**：灰底細框；選中時橘框＋橘字＋橘色淡底。
- **來源標籤**：小方標籤、淡底色字（站上計算＝藍、台服回報＝金、遊戲資料／社群整理比照辦理）。
- **表格**：表頭小灰字、底線分隔、偶數列極淡底、數字靠右等寬、重點數字橘色。
- **數值格**（怪物頁那種）：一格一個數值，小灰字標籤在上、大粗數字在下，格子用 1px 線分。
- **清單入口**（首頁右邊、查資料下半部）：一張卡裡多列，列之間 1px 線，右邊箭頭。
- **攻略文頂端**：主圖鋪滿寬度、往下漸層到底色，標題壓在圖上（候選-A）。電腦版右邊黏著本篇目錄。
- **「先講結論」框**：左邊 3px 橘線、每條前面兩位數編號（01、02…）。

### 圖示

候選圖上「怪、道、任」這種單字方塊只是佔位。實作時換成**遊戲裡的真圖**
（怪物圖 `public/assets/monster_frames`、道具圖、地圖縮圖），沒有合適的真圖就只放字、不放方塊。
不准用圖示庫、emoji。

## 範圍：哪些頁要改

全部的頁都會被第 1 步（換 token、換 utility）影響到。第 2 步以後逐頁收尾：

1. 共用：導覽列 `SiteHeader`、頁尾 `SiteFooter`、按鈕／選項 `ChoiceGroup`、`FilterTag`、`ProfileForm`
2. 攻略文 `JobArticleView`、`ArticleFold`、`ArticleList`、`/guides` 專區
3. 首頁（第一次來、已存角色兩種）、紙娃娃輪播
4. 查資料入口 `/db`、`DbBrowser`、各單筆頁（怪物、道具、任務、技能、地圖、NPC）、`SeoPage`
5. 工具頁：算傷害 `/plan/damage`、練功測速 `/plan/speed`、紙娃娃 `/plan/avatar`、組隊指揮 `/plan/pq`、
   公會徽章 `/plan/guild`、買齊任務 `/plan/buy`、楓幣匯率 `/price/fx`、未來視 `/future`、地圖導航 `/go`、野王計時
6. 其他：關於、隱私、條款、聯絡、活動頁

第 5 項的頁版面最複雜，這次沒畫候選圖；套用同一套規則，**做完每頁截圖給使用者看**，有疑問的再出 2～3 張候選。

## 交付方式

- 分好幾輪、一輪一個 PR，照 repo 既有流程：`feat/` 分支 → PR 進 `dev`（測試機）→ 使用者明講才上正式機。
- 建議順序：第 1 輪「token＋utility＋圓角＋字型」（全站一次換色，最大的視覺差異），
  第 2 輪起照上面範圍 1→6。每輪做完貼測試機網址＋改前改後截圖。
- 版號開工時再查 `origin/dev`、`origin/main` 最新的 `vX.YY`，別支 session 可能先佔。

## 必須跑的驗收（repo 既有工具）

- `scripts/verify/contrast-audit.mjs`：全站小字 AA（記得 `MSYS_NO_PATHCONV=1`）
- `scripts/verify/page-cls.mjs --all`：換頁跳動不能變差
- `scripts/verify/nav-fit.mjs`：手機、平板導覽列放得下
- `scripts/verify/home-first-frame.mjs`、`pages-first-frame.mjs`：第一格
- `npm test`、`next build`、PR 上「測試」三條綠
- 每輪自己用電腦＋手機寬度、深色＋淺色各截一次圖，對照候選圖

## 審稿後補的決定（我的判斷，使用者可推翻）

審稿人提了 5 題，都照既有規則或常理定下來，標「我的判斷」：

1. **攻略文「筆電 720 高第一個畫面就看到『先講結論』」照守。** 這是 `JobArticleView` 既有的規則，
   改版不能讓它變難用。所以電腦版主圖鋪滿但**高度要壓**（大約 240～280px），標題壓在圖下緣；
   每篇量一次（`article-layout.mjs`）。
2. **候選圖上現在沒有的呈現，分兩種：**
   - 換長相、資料已經有的 → 做。例如刷怪點數字加長條（數字本來就有）、電腦版出沒地圖／掉落物左右兩欄。
   - 要新資料或新判斷的 → 不做。例如掉落物用黃框標「任務要用」（現在沒有這個資料），怪物頁的兩顆新按鈕。
3. **上正式機的節奏：每輪只進 `dev`（測試機），全部做完、使用者看過才一起上正式機。**
   使用者中途明講要先上，才挑一部分上。為了不讓測試機半新半舊太久，**第 1 輪把共用的按鈕、選項、標籤一起改**
   （不只換顏色）。
4. **淺色模式的攻略文主圖：主圖那一塊固定深色**（圖往下漸層到深色、標題白字），下面內文才是淺色。
   圖上的字對比固定好量，不用兩套。做完淺色版截圖給使用者看。
5. **工具頁先合進 `dev`、再貼截圖給使用者看**，不用每頁開一個 PR 卡著等。使用者看了不要再改。
6. **來源標籤 6 種的顏色**：照「從哪來」分三組，不再多加顏色
   - 站上算的、遊戲本身的資料（站上計算、遊戲資料）→ 藍
   - 玩家說的（台服回報、社群整理）→ 金
   - 舊的、官方文字（舊版路線、官方公告）→ 灰（`--ink-soft` 字、`--paper-deep` 底）

## 留給實作的（builder 自己決定）

- token 值的微調（只要過 AA、看起來像候選圖）
- 每個 `rounded-full` 是頭像還是按鈕的判斷
- 元件要不要抽共用 class（例如 `.btn`、`.tag`）還是用 Tailwind 直接寫
- 攻略文主圖鋪滿時，手機版的高度和標題位置
